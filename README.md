# MeterFlow: Usage-Based API Billing Platform

## Problem Statement
Many developers build valuable APIs but struggle with the infrastructure required to monetize them effectively. Setting up rate limiting, usage tracking, user management, and billing integrations from scratch is complex, time-consuming, and prone to errors. Developers need a way to easily expose their APIs to customers, track how much they are used, and bill them accordingly without having to write this boilerplate code themselves.

## The Solution: MeterFlow
**MeterFlow** is a comprehensive Software-as-a-Service (SaaS) platform designed specifically for API providers. It acts as a "Smart Gateway" or proxy layer between the API consumer and the actual backend service (the "upstream" API).

Instead of clients calling your API directly, they call the MeterFlow proxy endpoint with an API key generated by MeterFlow. MeterFlow handles the authentication, rate limiting, and usage logging, and then transparently forwards the request to your actual API.

### Key Features
1. **User Authentication & Management:** Secure user registration, login, and profile management using JWTs.
2. **API Key Generation & Management:** Users can generate unique API keys, define the upstream URL they point to, and manage them (e.g., revoke or rotate keys for security).
3. **Smart Proxying:** MeterFlow acts as a reverse proxy, forwarding requests to the designated upstream URL while securely injecting necessary upstream credentials.
4. **Robust Rate Limiting:** Implements fast, atomic rate limiting (requests per minute/day) using Redis to protect APIs from abuse and enforce subscription quotas.
5. **Usage Tracking & Analytics:** Logs every request (endpoint, status code, response time) to a database and provides a real-time dashboard with charts (powered by WebSockets) for users to monitor their API usage.
6. **Tiered Subscription Billing:** Integrates with payment gateways (Stripe) and supports custom UPI payment flows, allowing users to subscribe to different tiers (e.g., Free, Starter, Pro) with varying rate limits.
7. **Webhooks:** Automated notifications to user-defined endpoints when specific events occur (e.g., approaching rate limits, payment success).
8. **Admin Dashboard:** A centralized panel for platform administrators to manage users and monitor the system.

## Tech Stack

The application is built using a modern, scalable, and robust technology stack:

### Frontend
* **React 18:** For building a fast, interactive user interface.
* **Vite:** A blazing fast frontend build tool.
* **Tailwind CSS:** For rapid, utility-first UI styling and responsive design.
* **React Query (TanStack Query):** For efficient data fetching, caching, and state management.
* **Recharts:** For rendering interactive usage and analytics charts.
* **Lucide React:** For beautiful, scalable vector icons.
* **React Router:** For seamless client-side navigation.

### Backend
* **Python 3.12:** The primary programming language.
* **FastAPI:** A modern, fast (high-performance) web framework for building APIs with Python, providing automatic Swagger documentation.
* **SQLAlchemy 2.0:** The Object-Relational Mapper (ORM) for interacting with the database using Python objects.
* **Uvicorn:** A lightning-fast ASGI server implementation.
* **HTTPX:** An asynchronous HTTP client for Python, used for proxying requests to upstream APIs.
* **Passlib & Bcrypt:** For secure password hashing.
* **Python-JOSE:** For generating and verifying JSON Web Tokens (JWT) for authentication.
* **WebSockets:** For real-time updates to the frontend dashboard.
* **Stripe Python Library:** For integrating subscription billing.

### Infrastructure & Data Storage
* **MySQL:** The primary relational database for storing user data, API keys, usage logs, and billing information. (Configurable via SQLAlchemy).
* **Redis:** An in-memory data structure store used for high-speed, atomic rate limiting.
* **Docker & Docker Compose:** For easy containerization, local development, and orchestration of the various services (Frontend, Backend, Database, Cache).
* **Kubernetes (K8s):** Production-ready deployment manifests are provided for scaling the application in a cloud environment.

## Architecture & Workflow

1. **Onboarding:** A developer signs up and creates an account on MeterFlow.
2. **Subscription:** The developer selects a subscription plan determining their rate limits.
3. **Key Generation:** The developer creates an API key in MeterFlow, specifying the destination "Upstream URL" of their actual API.
4. **Integration:** The developer provides the MeterFlow API key and the MeterFlow proxy URL to their customers.
5. **Request Handling:**
   - A customer makes a request to the MeterFlow proxy using the provided API key.
   - **Rate Limiting:** The `RateLimitMiddleware` intercepts the request. It checks Redis to see if the key has exceeded its allowed requests per minute or day. If so, it returns a `429 Too Many Requests` error.
   - **Proxying:** If the limit is not reached, the request is forwarded to the backend `proxy` route. This route uses `httpx` to forward the request to the target Upstream URL.
   - **Logging:** After the upstream API responds, MeterFlow calculates the response time, logs the usage data (status code, latency) to the database, and returns the response to the customer.
   - **Real-time Updates:** A WebSocket message is broadcast to the developer's dashboard, updating their usage charts instantly.

## Getting Started (Docker Compose)

The easiest way to run the application locally is using Docker Compose.

1.  Make sure you have Docker and Docker Compose installed.
2.  Clone the repository.
3.  Run the following command in the root directory:
    ```bash
    docker-compose up -d --build
    ```
4.  The frontend will be available at `http://localhost:3000` (or `5173` depending on your vite config) and the backend API documentation will be at `http://localhost:8000/docs`.

## Kubernetes Deployment

Manifests for deploying MeterFlow to a Kubernetes cluster are provided in the `k8s/` directory.

1. Ensure your Kubernetes cluster is running and `kubectl` is configured.
2. Apply the manifests:
   ```bash
   kubectl apply -f k8s/mysql-deployment.yaml
   kubectl apply -f k8s/redis-deployment.yaml
   kubectl apply -f k8s/backend-deployment.yaml
   kubectl apply -f k8s/frontend-deployment.yaml
   ```
